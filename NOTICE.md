where, under what terms, and what was changed. It is not a formality: the two upstreams are
under *different* copyleft licences, and the combination is what decides the licence of the
APK you install.

## Why the whole app is AGPL v3

The Stellarium Web Engine is licensed under the **GNU Affero GPL v3**, which is strictly
stronger than the GPL v3 that Sky Map uses: it adds section 13, the network clause. GPLv3 §13
explicitly permits linking GPLv3 work with AGPLv3 work, and the result is that the AGPL's terms
govern the combined program.

So: **the built APK is AGPL v3.** In practice, for a sky app that runs entirely on the phone
with no server, this means the same thing GPLv3 would — ship the source with any binary you
distribute. The repository is public, which satisfies it.

The individual `android/` sources stay GPL-v3-*or-later*, and that "or later" is not
decoration: it is the clause that makes the combination legal in the first place. Do not
narrow a file's header to bare GPLv3.

`android/ASSET-LICENSES.txt` remains the authoritative, file-by-file list for that module's
assets, including which scientific imagery is NASA/ESA public domain and which is CC BY 4.0.

## What was changed

### Sky Map v2 → `android/`

- Renamed to Astrology Nova: application id `app.astrologynova` (the Kotlin package namespace
  is deliberately left as `com.google.android.stardroid`, so upstream fixes still merge).
- Re-themed to Nova's palette. See the trade-off recorded in `ui/theme/Theme.kt`: upstream's
  amber was chosen partly because it is kind to dark adaptation, and cyan is not.
- **Every All-Rights-Reserved brand asset was replaced**, not copied. Upstream reserved its
  launcher icon, notification glyph, onboarding backdrop and sky-marker set precisely so that
  a fork could not ship them, and this fork does not. The replacements are original artwork
  for Astrology Nova, generated by `android/tools/generate_welcome_bg.py` and
  `android/tools/generate_marker_icons.py` or authored as vector drawables. There is no
  `[arr]` section left in `ASSET-LICENSES.txt`.
- Added the deep-sky view (`ui/deepsky/`) and the Gradle wiring that stages `web/` into the
  app's assets.
- **Removed upstream's release machinery**: `fastlane/` (whose `Appfile` pointed at Sky
  Map's own Play Store listing, and whose `metadata/` held their store copy and
  screenshots in 28 languages), the `Gemfile` that drove it, and the four Claude skills
  that deploy releases and answer Play Store reviews. Keeping any of it would have aimed
  a future contributor — or an agent — at someone else's listing and users.

Upstream's `android/docs/` still describes Sky Map and has not been rewritten; treat it as
history rather than as this app's specification.

### Stellarium Web Engine → `engine/`

The engine was last built against emscripten 1.39/1.40 (2020) and does not compile with a
current toolchain. Four changes in `engine/SConstruct` and one in `engine/src/js/obj.js` fix
that; each is marked with an `Astrology Nova:` comment in the source:

1. `EXTRA_EXPORTED_RUNTIME_METHODS` → `EXPORTED_RUNTIME_METHODS` (renamed upstream in
   emscripten 2).
2. `_malloc` / `_free` moved from the runtime-methods list to `EXPORTED_FUNCTIONS`, where
   they now belong.
3. Link-only settings are no longer passed on the compile line — modern `emcc` reports that as
   `-Wunused-command-line-argument`, which the engine's `-Werror` makes fatal.
4. `-Wno-deprecated-non-prototype` and `-Wno-unused-but-set-variable`, for warnings clang has
   added since 2020. The first fires on the vendored K&R-era zlib; neither indicates a defect.
5. `Module.writeAsciiToMemory` (removed from emscripten) → `Module.stringToUTF8`, which also
   makes the call correct for non-ASCII strings rather than merely working again.

6. `Module.preserveDrawingBuffer` is now honoured instead of hard-coded to false
   (`src/js/pre.js`). Default unchanged, and **the app does not turn it on**: preserving the
   drawing buffer every frame costs real time on a tile-based mobile GPU, permanently, to
   serve a button pressed occasionally. The screenshot rides the engine's own frame instead
   (see `capture()` in `web/index.html`). The option is kept as an escape hatch in case that
   ordering ever stops holding.

`web/index.html` also carries ports of two files from Astara's Vue frontend, which is AGPL
like the engine: `gyroscope-service.js` (the W3C-device-orientation to OBSERVED-frame
derivation, the roll that keeps the horizon level, and the adaptive smoothing gain) and
`camera-service.js` (the getUserMedia constraints). Both were reduced to plain JavaScript
with the Vue store and the Capacitor screen-orientation lock removed. The composited capture
is not theirs — theirs saves the camera frame alone.

`web/js/stellarium-web-engine.{js,wasm}` are the **build output** of the above, committed on
purpose: with them present the APK builds with nothing but the Android SDK, and emscripten is
needed only to change the engine itself.
